```json
      "profection_family": {...},

  }

```

**状态字段说明**：

| 状态 | 含义 | 触发条件 |
|------|------|----------|
| **success** | 任务完成，输出可用 | 所有Step执行完毕，输出契约完整 |
| **failed** | 任务失败，需要主Agent决策 | 输入数据缺失、知识库加载失败、校验错误 |
| **partial** | 部分完成，标记缺失 | 某些Step数据不完整，但核心输出可用 |

**error字段格式**：

```json
{
  "error": {
    "code": "INVALID_INPUT|KB_LOAD_FAILED|STEP_FAILED",
    "message": "具体错误描述",
    "step": "失败的Step编号"
  }
}
```

### 禁止任务

```
✗ 禁止输出打分（如"父母：4分"）
✗ 禁止父母层次低=刑克父母的判断
✗ 禁止滥用转宫法
✗ 禁止模糊时间表述（如"近期"）
✗ 禁止跳过数据直接解读
✗ 禁止在未输出rules_read时继续执行
✗ 禁止跳过KVP验证直接解读数据
```

## 四、工作流程

### Step -1: 顾客问题确认与专项链路选择

**前置知识**：
```
读取：knowledge/专项解盘思维链与沟通规范.md（规则型）
时机：before_execution
```

**执行步骤**：
```
1. 确认顾客真正问题：长期格局/当前处境/具体决策/未来时间窗口
2. 按主题选择入口宫位与自然征象星，不泛泛论盘
3. 建立技术链：主题宫位 -> 宫主星 -> 宫主落宫 -> 自然征象星 -> 结构 -> 命主关系 -> 推运
4. 输出时转化为顾客语言：结论 -> 依据 -> 现实表现 -> 可执行建议
5. 检查表达边界：概率语言、选择语言、负面判断后必须给化解建议
```

## 五、输出格式规范

### synthesis字段规范

> **核心要求**：必须是具体描述，禁止打分，必须区分层次与关系

**正确示例**：
```
"father_level_synthesis": "父亲层次中等偏高，太阳入庙得贵气，四宫主木星与太阳形成六合结构，有贵人支持。实例：父亲可能在教育行业或政府机构工作，有一定社会地位和稳定收入。"

"father_relationship_synthesis": "与父亲关系整体和谐，征象星太阳无严重受克。但土星（转宫8r）与太阳有刑相，可能存在一些代沟或沟通障碍。实例：可能与父亲在某些价值观上有分歧，但整体关系尚可。"
```

**错误示例**：
```
"father_level_synthesis": "父亲：4分"  ✗ 禁止打分
"father_level_synthesis": "父亲层次低"   ✗ 禁止笼统表述
```

### forecast字段规范

```json
{
  "forecast": {
```
