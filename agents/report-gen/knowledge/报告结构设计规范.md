## 一、结构设计原则

### 1.1 四大原则

| 原则 | 说明 | 具体做法 |
|------|------|----------|
| **视觉清晰** | 一眼能看清结构 | 减少代码块，多用引用和表格 |
| **层次分明** | 标题层级清晰 | H1→H2→H3，不超过4层 |
| **易于扫描** | 快速找到关键信息 | 关键信息用Callout突出 |
| **具体可操作** | 每个建议都有具体举例 | 避免"需要建立边界"等抽象表述 |

### 1.2 具体化要求（★核心★）

```
┌──────────────────────────────────────────────────────────────┐
│                ★ 具体化三要素 ★                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  【要素一：具体举例】                                         │
│  ├─ 每个建议必须有具体场景举例                                │
│  ├─ 例：不说"建立边界"，说"工作日19点后不处理工作邮件"        │
│  └─ 例：不说"注意健康"，说"每周3次30分钟有氧运动"            │
│                                                              │
│  【要素二：具体时间】                                         │
│  ├─ 每个判断必须有具体时间节点                                │
│  ├─ 例：不说"近期"，说"2026年Q3-Q4"                         │
│  └─ 例：不说"长期"，说"2029年月亮大运开始后"                │
│                                                              │
│  【要素三：具体行动】                                         │
│  ├─ 每个建议必须有可执行的具体步骤                            │
│  ├─ 例：不说"学习心理学"，说"2026年报考心理咨询师培训班"    │
│  └─ 例：不说"主动社交"，说"每周参加1次兴趣社群活动"          │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 排版元素使用指南

| 元素 | 使用场景 | 示例 |
|------|----------|------|
| **代码块** | 仅用于数据表、计算过程 | 行星位置数据表 |
| **引用块** | 核心结论、重要提示 | > 核心结论：... |
| **Callout** | 关键发现、警示信息 | > [!important] 关键发现 |
| **表格** | 数据对比、列表展示 | 宫位配置表 |
| **列表** | 多项并列内容 | 化解建议 |
