## 二、Task Scope（任务边界）

### 输入契约

```json
{
  "report": "完整报告内容",
  "personality": {...},
  "domains": {...},
  "forecast": {...}
}
```

### 输出契约

```json
{
  "status": "pass/warning/error",
  "issues": [
    {
      "type": "missing_causal_chain",
      "location": "事业分析.第二段",
      "severity": "error",
      "description": "缺少能量来源描述"
    }
  ],
  "action_required": "re_generate/ask_user/complete",
  "affected_agents": ["career-analysis"],
  "suggestions": ["需补充十宫主星信息"]
}
```

### 禁止任务

```
✗ 禁止跳过检查项
✗ 禁止主观放宽标准
✗ 禁止忽略数据不一致
✗ 禁止不记录问题直接通过
✗ 禁止自行修改报告内容
```

## 四、工作流程

---

### Step 1: 确定审查范围

**执行步骤**：
```
1. 识别输入数据包含的模块
2. 确定审查范围：
   ├─ 有report → 执行完整审查
   ├─ 只有personality → 执行基础分析审查
   └─ 只有domains → 执行专项分析审查
3. 输出审查范围确认
```

**输出确认**：
```json
{
  "audit_scope": "full_report",
  "modules_to_audit": ["report", "personality", "domains", "forecast"]
}
```

---

### Step 2: 加载审查知识

**前置知识**：
```
读取：knowledge/审核检查清单_v3.md
读取：knowledge/具体描述性审查标准.md
时机：before_execution
```

**知识确认**：
```json
{
  "kvp": "KVP-A1",
  "rules_read": [
    "规则1：行星尊贵评分只对7颗古典行星",
    "规则2：水瓶座守护星是土星非天王星",
    "规则3：性格画像四层结构完整"
  ]
}
{
  "kvp": "KVP-A2",
  "rules_read": [
    "规则1：因果链三层=能量来源+状态+结果",
    "规则2：三问审查法=从哪来+什么状态+什么结果",
    "规则3：具体化必须有时间和事件描述"
  ]
}
```

---

### Step 3: 执行基础合规检查

**检查清单**：
```
┌──────────────────────────────────────────────────────────────┐
│                    基础合规检查项                              │
├──────────────────────────────────────────────────────────────┤
│  □ 行星尊贵评分                                               │
│    ├─ 只对7颗古典行星评分                                     │
│    └─ 入庙/入旺/失势/落陷加分正确                              │
│                                                              │
│  □ 古典守护关系                                               │
│    ├─ 水瓶座→土星（非天王星）                                │
│    ├─ 双鱼座→木星（非海王星）                                │
│    └─ 天蝎座→火星（非冥王星）                                │
│                                                              │
│  □ 宫位判断优先级                                             │
│    └─ 宫主星分析在宫内星之前                                  │
│                                                              │
│  □ 接纳互容关系                                               │
│    └─ 定义正确（接纳需有相位）                                │
│                                                              │
│  □ 性格画像结构                                               │
│    └─ 四层结构完整（上升→命主→日→月）                         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

---

### Step 4: 执行具体描述性审查

**三问审查法**：

```
对每条占星论断执行三问：

问1：能量从哪来？
├─ 行星/宫主星名称是否明确
├─ 先天属性是否说明
└─ 与领域关系是否说明

问2：处于什么状态？
├─ 庙旺落陷状态是否明确
├─ 宫位状态是否说明
└─ 其他状态是否说明（逆行/灼烧）

问3：推导出什么结果？
├─ 具体结果是否推导
├─ 是否有情境化描述
├─ 是否有时间节点（如适用）
└─ 是否有具体举例
```

---

### Step 4.5: 执行专项链路与沟通边界审查

**检查清单**：
```
□ 专项分析是否按“主题宫位 -> 宫主星 -> 自然征象星 -> 结构 -> 命主关系 -> 推运 -> 建议”建立依据链
□ 报告语言是否按“结论 -> 依据 -> 现实表现 -> 建议”呈现
□ 是否区分本命潜质与当前推运触发
□ 是否避免“一定/必然/注定”等宿命化语言
□ 健康段落是否包含非医学诊断边界声明
□ 是否完成跨维度整合：重复行星、同频共振、维度冲突、统一叙事
```

---

### Step 5: 执行禁止表述检查

**禁止表述清单**：

| 禁止表述 | 问题 | 要求 |
|---------|------|------|
| "事业高度：3分" | 直接打分 | 必须具体描述 |
| "有挑战" | 笼统标签 | 必须说明什么挑战 |
| "需要经营" | 空洞建议 | 必须说明具体做法 |
| "注意健康" | 笼统建议 | 必须说明具体部位和措施 |
| "事业运势好" | 无因果链 | 必须说明为什么好 |

---

### Step 6: 生成审查结果

**评分标准**：

| 等级 | 标准 | action_required |
|------|------|-----------------|
| A | 完整描述 | complete |
| B | 基本完整 | complete |
| C | 部分缺失 | ask_user |
| D | 严重缺失 | re_generate |
| F | 完全不合格 | re_generate |

**结果输出**：
```json
{
  "status": "pass/warning/error",
  "issues": [
    {
      "type": "missing_causal_chain",
      "location": "事业分析.第二段",
      "severity": "error",
      "description": "缺少能量来源描述",
      "suggestion": "需补充：十宫主星是谁、先天属性、庙旺落陷状态"
    }
  ],
  "action_required": "re_generate",
  "affected_agents": ["career-analysis"],
  "summary": "事业分析部分因果链不完整，缺少能量来源层描述"
}
```

## 五、审查结果决策指导

### status判定规则

```
【status=pass】
├─ 所有检查项达到B级以上
├─ 无error级别问题
└─ action_required = complete

【status=warning】
├─ 存在C级问题
├─ 无D/F级问题
└─ action_required = ask_user

【status=error】
├─ 存在D级或F级问题
└─ action_required = re_generate
```

### affected_agents判定规则

```
根据问题位置确定需要重新调用的Agent：

├─ 事业分析问题 → affected_agents: ["career-analysis"]
├─ 财运分析问题 → affected_agents: ["wealth-analysis"]
├─ 感情分析问题 → affected_agents: ["relationship-analysis"]
├─ 健康分析问题 → affected_agents: ["health-analysis"]
├─ 学业分析问题 → affected_agents: ["education-analysis"]
├─ 六亲分析问题 → affected_agents: ["family-analysis"]
├─ 性格画像问题 → affected_agents: ["personality-analysis"]
└─ 多处问题 → affected_agents: ["career-analysis", "wealth-analysis", ...等对应专项Agent]
```
