# 数据核对强制规则

> **用途**：确保所有判断基于排盘脚本原始数据，禁止主观推断
> **版本**：v1.0 | 2026-06-08
> **重要级别**：★ 强制执行 ★
> **来源**：基于实际错误案例分析

---

## 一、核心原则

```
┌──────────────────────────────────────────────────────────────┐
│              ★ 数据核对强制原则 ★                             │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  【原则一】所有数据必须从原始输出读取                          │
│  ├─ 行星状态 → 从 planets JSON 字段读取                       │
│  ├─ 宫头星座 → 从 houses JSON 字段读取                        │
│  ├─ 相位数据 → 从 aspects 数组读取                            │
│  └─ 禁止主观推断、猜测、记忆补充                              │
│                                                              │
│  【原则二】宫头星座 ≠ 行星所落星座                             │
│  ├─ 宫头星座：宫位起始点的星座（从 houses 字段读取）           │
│  ├─ 行星所落星座：行星所在的星座（从 planets 字段读取）        │
│  ├─ 这两个概念完全不同，必须区分                              │
│  └─ 禁止用行星位置推断宫头位置                                │
│                                                              │
│  【原则三】每个判断必须标注数据来源                            │
│  ├─ "土星落陷" → 标注：(来源: JSON Saturn.dignity)           │
│  ├─ "土星无逆行" → 标注：(来源: JSON Saturn.retrograde: false)│
│  ├─ "10宫主是木星" → 标注：(来源: 10宫宫头双鱼座18.82°)       │
│  └─ 无标注的判断视为错误                                      │
│                                                              │
│  【原则四】先读数据，再下判断                                  │
│  ├─ 步骤：读取原始数据 → 提取字段 → 下判断                    │
│  ├─ 禁止：先下判断 → 再找数据支撑                             │
│  └─ 这是"数据驱动"的核心要求                                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 二、常见错误案例警示

### 错误案例1：逆行状态推断错误

```
【错误案例】

错误判断：
  "土星逆行(-2分)"

数据事实：
  ├─ JSON Saturn.retrograde: false
  ├─ JSON Saturn.speed: 0.1097（正值=顺行）
  └─ 结论：土星无逆行

错误原因：
  ├─ 看到火星逆行，错误类推土星也逆行
  ├─ 没有核对 retrograde 字段
  └─ 主观推断替代数据核对

正确做法：
  ├─ 从 JSON 读取 retrograde 字段值
  ├─ 标注来源：(来源: JSON Saturn.retrograde: false)
  └─ 如不确定，先核对再下判断
```

### 错误案例2：宫主星推断错误（最严重）

```
【错误案例】

错误判断：
  "10宫主是火星（白羊座）"

数据事实：
  ├─ JSON houses.10.cusp_lon: 348.82°
  ├─ JSON houses.10.sign_cn: "双鱼座"
  ├─ JSON houses.10.sign_en: "Pisces"
  ├─ 双鱼座古典守护是木星
  └─ 结论：10宫主是木星

错误思维路径：
  ├─ 看到土星落在白羊座10宫
  ├─ 错误认为：土星在白羊座 → 白羊座是10宫头 → 火星是10宫主
  ├─ 混淆了"行星所落星座"与"宫头星座"
  └─ 没有直接读取 houses 字段

正确思维路径：
  ├─ 从 houses 字段读取10宫宫头
  ├─ 10宫宫头是双鱼座(18.82°)
  ├─ 双鱼座古典守护是木星
  └─ 10宫主是木星

影响：
  ├─ 官禄星判断错误
  ├─ 整个事业分析方向错误
  └─ 这是断局最基础的数据错误
```

### 错误案例3：数据来源缺失

```
【错误案例】

错误判断：
  "火土对冲容许度0.39°"（无来源标注）

问题：
  ├─ 没有标注数据来源
  ├─ 无法验证判断正确性
  └─ 后续审核无法追溯

正确做法：
  "火土对冲容许度0.39°(来源: 相位表 Mars-Saturn Opposition)"
```

## 三、数据核对标准流程

```
┌──────────────────────────────────────────────────────────────┐
│                    数据核对标准流程                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Step 1: 运行排盘脚本                                         │
│  ├─ 使用 astro_calc.py 生成完整JSON数据                       │
│  └─ 输出包含 planets、houses、aspects 等字段                  │
│                                                              │
│  Step 2: 创建数据对照表（★强制★）                              │
│  ├─ 行星状态对照表：列出所有行星的 retrograde 字段值           │
│  ├─ 宫位配置对照表：列出所有宫位的宫头星座和度数               │
│  ├─ 相位对照表：列出所有相位的容许度                          │
│  └─ 每个表标注数据来源字段                                    │
│                                                              │
│  Step 3: 核对关键判断                                         │
│  ├─ 宫主星：从宫头星座判断，标注来源                          │
│  ├─ 逆行状态：从 retrograde 字段读取                          │
│  ├─ 尊贵状态：从 dignity 字段读取                             │
│  └─ 相位容许度：从相位表读取                                  │
│                                                              │
│  Step 4: 每个判断标注来源                                     │
│  ├─ 格式：(来源: JSON字段名/相位表/宫位表)                     │
│  ├─ 关键判断必须标注                                         │
│  └─ 审核时追溯来源                                           │
│                                                              │
│  Step 5: 自我审核                                             │
│  ├─ 检查是否有无依据的判断                                    │
│  ├─ 检查是否有"推断"而非"读取"的数据                          │
│  └─ 检查宫头星座是否与行星所落星座混淆                        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 五、禁止行为清单

```
┌──────────────────────────────────────────────────────────────┐
│                    ★ 禁止行为清单 ★                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  【禁止一】主观推断逆行状态                                    │
│  ├─ ✗ "土星应该逆行吧"                                        │
│  ├─ ✗ "这个时间段土星可能逆行"                                │
│  └─ ✓ 从 retrograde 字段读取数据                             │
│                                                              │
│  【禁止二】用行星位置推断宫头                                  │
│  ├─ ✗ "土星在白羊座10宫 → 10宫头是白羊座 → 10宫主是火星"      │
│  ├─ ✗ "火星落在X宫 → X宫宫头是火星所在星座"                   │
│  └─ ✓ 从 houses 字段读取宫头星座                             │
│                                                              │
│  【禁止三】无数据来源的判断                                    │
│  ├─ ✗ "火土对冲容许度很紧"（无数据）                          │
│  ├─ ✗ "日月有相位"（无计算）                                  │
│  └─ ✓ 每个判断标注来源                                       │
│                                                              │
│  【禁止四】先判断后找数据                                      │
│  ├─ ✗ 先写"土星逆行" → 再试图证明                            │
│  ├─ ✗ 先写结论 → 再补数据                                    │
│  └─ ✓ 先读数据 → 再下判断                                    │
│                                                              │
│  【禁止五】混淆概念                                            │
│  ├─ ✗ 混淆"行星所落星座"与"宫头星座"                          │
│  ├─ ✗ 混淆"行星位置"与"宫位起始点"                            │
│  └─ ✓ 明确区分两个概念                                       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 六、自我审核检查清单

在每个分析完成后，必须执行以下自我审核：

```markdown
□ 所有逆行状态是否从 retrograde 字段读取？
□ 所有宫主星是否从宫头星座判断？
□ 所有尊贵状态是否从 dignity 字段读取？
□ 所有相位容许度是否从相位表读取？
□ 关键判断是否标注数据来源？
□ 是否有"应该""可能""大概"等推断性表述？
□ 是否混淆了行星所落星座与宫头星座？
□ 数据对照表是否已创建并核对？
```

## 七、修正后的正确示例

### 示例：10宫分析

```
【正确做法】

数据提取：
1. 从 JSON houses.10 读取：
   ├─ cusp_lon: 348.82°
   ├─ sign_cn: "双鱼座"
   ├─ sign_en: "Pisces"
   └─ cusp_deg: 18.82°

2. 判断宫主星：
   ├─ 宫头星座：双鱼座
   ├─ 古典守护：木星
   └─ 宫主星：木星（来源: 10宫宫头双鱼座18.82°）

3. 木星状态：
   ├─ 位置：水瓶座8宫（来源: JSON Jupiter.ecl_lon: 306.41°）
   ├─ 尊贵：中性（来源: JSON Jupiter.dignity: "入闲(中性)"）
   ├─ 逆行：否（来源: JSON Jupiter.retrograde: false）
   └─ 总分：-2分（来源: 计算）

4. 10宫内星：
   ├─ 无宫内行星（来源: 宫位配置表）

5. 官禄星判断：
   ├─ 官禄星 = 10宫主 = 木星
   ├─ 木星状态：失势，能量受限
   └─ 事业需努力经营
```
